# CORS Implementation Plan — deleting a permission nobody uses

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** written 2026-08-21, not implemented.

**Goal:** remove CORS from Rail Baron and Acquire entirely — six sites and two
production dependencies — so all three games are same-origin only, which is
what Marco Polo has always been and what every client has needed since the
origin-relative work landed.

**Architecture:** deletion, not configuration. No allowlist, no environment
variable, no shared helper. The tests that hold it in place assert on
**response headers**, because every wire-level test in this repo drives
socket.io from Node and Node ignores CORS — a behavioural test here passes
whatever the policy is, and would be worse than no test.

**Tech Stack:** nothing added. `cors@^2.8.6` and `@types/cors@^2.8.19` leave
Rail Baron's and Acquire's `package.json`.

**Spec:** none separate; this document is the design record, as with
[the linter](2026-08-20-the-linter.md) and
[the room store](2026-08-20-room-store.md). It closes the fifth and last of
the [cutover](2026-08-19-cutover.md)'s deliberate deferrals.

## Why deletion rather than an allowlist

The cutover plan deferred this with a sentence that assumed the answer: *"This
plan finally creates the single public origin that makes narrowing it easy."*
Narrowing to that origin is indeed easy. It is also unnecessary, because by
the time the origin existed there was nothing left to narrow.

**Nothing in this repo makes a cross-origin request.** Checked rather than
assumed, on 2026-08-21:

- **Zero `fetch()` calls in any of the three clients.** Not one. Every client
  reaches its server over socket.io, addressed as a path off
  `window.location.origin` ([origin-relative
  clients](2026-08-18-origin-relative-clients.md), 2026-08-18).
- **The only HTTP routes any game registers are `/health` and static assets.**
  So the express `cors()` middleware's entire practical effect is to let
  scripts on other sites read your health JSON and your JavaScript bundles.
- **No build sets `VITE_SERVER_URL`.** Acquire's `.env.production` was deleted
  2026-08-20 and Rail Baron never had one. The client code path survives in
  `src/config.ts` and `src/net/connection.ts`, but nothing feeds it.
- **Dev is same-origin too.** The Vite proxy forwards server-side; the browser
  only ever talks to the dev server's own origin.

**And the experiment has already been run.** Marco Polo has never had CORS —
not a single reference in `games/marcopolo/server/` — and it works on the LAN,
on Render, standalone, and composed. Rail Baron and Acquire carry `origin:
'*'` because they were written as separate repos with separate origins, and
that stopped being true a migration ago.

An allowlist would add configuration that has to be correct in two
deployments in order to permit requests that nobody makes. Deleting the
middleware is fewer moving parts, and it fails closed.

## What this does not do, said plainly

**This is not a defence, and the commit message must not imply one.** It
removes a permission nobody was using. Specifically, it does **not** stop a
page on another origin from opening a socket to these servers:

Browsers do not apply CORS to the WebSocket handshake. socket.io's `cors`
option only ever governed the HTTP long-polling transport, so a hostile page
that connects with `transports: ['websocket']` was never affected by it and
still is not. Restricting *who may open a socket* needs `allowRequest` on each
`Server`, inspecting the `Origin` header — considered and deliberately
declined on 2026-08-21, because these are LAN party games with no cookie auth,
no credentials to steal via an ambient-authority request, and a real cost to
getting it wrong (people reach the host by IP, by hostname, and by `.local`
name, and an over-strict check locks out the living room).

Anyone reading "CORS tightened" later and inferring "sockets are origin-locked"
would be wrong, which is why this paragraph exists.

## Why the tests assert headers and not behaviour

The obvious test — connect from a disallowed origin, expect failure — cannot
be written here, and writing it anyway would be actively harmful.

`socket.io-client` under Node is not a browser. It does not implement the
same-origin policy, does not send an `Origin` header it did not choose, and
never refuses a response for want of `Access-Control-Allow-Origin`. Every wire
test in this repo — `clientOverWire.test.ts`, `projectionOverWire.test.ts`,
`lobbyConformance.test.ts`, `goldenSocket.test.ts` — therefore passes
identically with `origin: '*'`, with a strict allowlist, or with no CORS at
all. A green suite says nothing about this change in either direction.

So the assertions are on the response: `GET <base>/health` sent **with** an
`Origin: https://evil.example` header must come back 200 and with **no**
`access-control-allow-origin` header. That is a real observation of the thing
that actually changed, and it fails today.

## Global Constraints

- **Deletion only.** No allowlist, no `ALLOWED_ORIGINS`, no `allowRequest`, no
  shared CORS helper in `packages/host`. If a task seems to want one, stop —
  that is a different plan and it needs its own decision.
- **Marco Polo is not edited.** It has no CORS to remove. It is the control.
- **`npm test` must still report every existing test passing** — 1658 / 160
  files before this plan, 1661 after, since the three new tests are appended
  to files that already exist.
- **`npm run lint` must stay green** (it landed on `main` 2026-08-21, PR #10).
- **Both boot paths keep working.** Each game's standalone `createServer()` /
  `startServer()` and its `mount(ctx)` are separate code paths, and Acquire's
  standalone had CORS the composed path did not. Both get an assertion.

## Deliberately not in this plan

- **`allowRequest` origin enforcement.** The only thing that would actually
  restrict who may open a socket, and declined on 2026-08-21: LAN games, no
  cookie auth, nothing to steal by ambient authority, and a real risk of
  locking out a living room that reaches the host by IP or `.local` name. If
  it is ever wanted, it is its own plan and it starts by enumerating how
  people actually reach the host.
- **Removing the `VITE_SERVER_URL` client code path.** Now unused by every
  build, and therefore tempting. It is also the only seam that would let a
  client talk to a server on another origin again, it costs nothing to keep,
  and deleting it is unrelated to deleting a server policy. Separate decision.
- **A shared CORS helper in `packages/host`.** There is no CORS left to share.
- **Content-Security-Policy, `X-Frame-Options`, or any other header hardening.**
  Real topics, none of them this one. Framing and CSP are not CORS, and
  conflating them is how a small deletion turns into a security review.
